# skill 知识图谱

`skm graph` 会把已安装的 skill、MCP、分类、目录前缀套件和平台生态关系构造成知识图谱。

## 快速使用

```bash
skm graph
skm graph --format html --output skill-graph.html
skm graph --format json --output skill-graph.json
skm graph --format mermaid --output skill-graph.md
```

HTML 图谱是零依赖单文件，内联 SVG/CSS/JS，可直接用浏览器打开，不需要联网，也不会读取或上传额外数据。

## 节点类型

| 节点 | 含义 |
|---|---|
| `skill` | 合并后的 skill 能力节点，带分类、工具来源、使用次数、最近使用、上下文估算等信息 |
| `mcp` | MCP server 节点，带工具来源、transport、使用次数 |
| `category` | 分类节点，每个分类独立展示其成员 skill |
| `family` | 目录前缀推断的套件节点，例如 `baoyu-*`、`lark-*`、`gsap-*`；不等于已证明同一作者或仓库 |
| `platform` | 平台节点，例如 WeChat、Lark、GitHub、X / Twitter、OpenAI；每个平台是独立节点 |

## 关系类型

| 关系 | 详细含义 | 适合用来判断什么 |
|---|---|---|
| 套件归属 | 目录名前缀相同，推断属于同一套件，例如 `baoyu-*`、`lark-*`、`gsap-*`；不据此声称同一作者或真实同源 | 哪些 skill 是成组安装的套件，一组里是否有明显冗余 |
| 分类归属 | skill 连接到分类规则产生的具体分类节点，不代表同分类 skill 互相依赖 | 某一类能力是否过多，做同类任务时有哪些候选 |
| 重复 | 不同安装记录的 `SKILL.md` 内容哈希完全相同，表示实质上是同一份 skill | 是否可以保留一份、软链化或禁用重复项 |
| 强替代 | 同分类下名称或描述高度相似，但不属于同一前缀组，且相似度更高 | 哪些 skill 很可能互为替代，适合进一步人工确认 |
| 弱替代 | 同分类下名称或描述有一定相似度，但证据弱于强替代 | 哪些 skill 可能有功能重叠，适合在大类梳理时参考 |
| 流程 | 一个 skill 的输出格式可以作为另一个 skill 的输入格式，例如 URL 转 Markdown 后再转 HTML | 哪些 skill 可以串成工作流 |
| 上下游 | 一个 skill 明确偏“抓取/读取/提取/生成输入”，另一个 skill 明确偏“发布/写入/上传/渲染输出” | 哪些能力可能天然前后衔接 |
| 共享格式 | 两个 skill 共同涉及 Markdown、HTML、PDF、JSON、CSV、PNG、MP4 等输入/输出格式 | 哪些 skill 可以围绕同一种内容格式组合 |
| 反向转换 | 两个 skill 的转换方向相反，例如 Markdown 转 HTML 与 HTML 转 Markdown | 哪些 skill 是互补工具，而不是简单重复 |
| 平台归属 | 名称或描述命中一个具体外部平台节点，例如 GitHub、飞书、Notion、WeChat | 分别查看各平台生态，识别某个平台相关 skill 是否过多 |
| 平台内分工 | 根据关键词推断多个 skill 面向同一平台但动作不同，例如搜索、发布、摘要、下载 | 人工核对同一平台生态里有哪些可组合动作 |
| 使用 MCP | skill 描述中同时命中 MCP 与具体 MCP server 名称，表示它可能依赖或调用该 MCP 能力 | 哪些 skill 可能与某个 MCP server 相关 |

## 图谱摘要

JSON/HTML 图谱会附带摘要，帮助你先看结论再看细节：

- 最密集套件：套件归属关系最多的 skill 组
- 重复核心：内容完全相同或实体双份的重复区域
- 平台生态：围绕 GitHub、飞书、WeChat、Notion 等平台形成的能力组
- 潜在工作流：由流程、上下游、共享格式推断出的可串联组合

## HTML 交互

- 关系过滤：左侧勾选哪些关系，右侧只显示这些关系涉及的节点和连线
- 默认聚焦高信号关系：默认显示套件归属、重复、强/弱替代、流程、反向转换、使用 MCP
- 节点上限：大图可只显示高信号节点，按使用次数、关系数量、重复安装等排序；搜索时会临时放开上限，避免精确目标被隐藏
- 关系说明提示：鼠标悬停关系名称会显示详细解释
- 搜索聚焦：搜索框会在当前子图中显示匹配节点及其一跳关系
- 重点节点：只看使用过、重复安装或关系较多的关键 skill
- 闲置隐藏：隐藏从未使用的 skill，压缩大图
- 标签开关：节点太密时可以临时关闭文字标签
- 节点拖动：右侧图谱节点可拖动，相连线段实时跟随
- 缩放适配：支持放大、缩小和适配当前可见节点
- 重置布局：手工拖动后可回到初始布局
- 悬停详情：查看来源、置信度、使用次数、最近使用、上下文估算等信息

## 查看建议

- 只看套件关系：保留“套件归属”，关闭其他关系
- 查看工作流：打开“流程”“上下游”“共享格式”，必要时再打开“反向转换”
- 查看平台生态：打开“平台归属”，搜索 `github`、`飞书`、`notion` 等关键词
- 图太密时：先把“节点上限”调到高信号 Top 60/100，关闭“分类归属”“平台归属”，开启“只看重点节点”或“隐藏从未使用的 skill”，再点击“适配视图”

在 `skm web` 工作台中，还可以通过“聚焦范围”直接选择某个具体套件、平台或分类。例如选择 `baoyu-*` 时，只显示该套件成员；选择 `GitHub` 时，只显示 GitHub 平台成员及成员间当前已启用的关系。节点关系证据会标记为“明确”“结构”或“推断”，避免把关键词或目录前缀推断误当成事实。

## 视觉规则

- 节点大小与使用频率相关，越常用越大
- 从未使用的 skill 会变灰
- 两侧实体双份安装的 skill 会用红色边框强调
- 分类、前缀套件、平台、MCP 使用不同颜色
- 画布会随 skill 数量自动变大，减少大量节点时的默认重叠
- 初始布局会进行轻量碰撞避让，降低大量 skill 时节点和标签重叠
